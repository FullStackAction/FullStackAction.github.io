Flutter 居然能直接跑在 Apple Watch 上了？玩转 flutter-watchos

欢迎关注微信公众号：[FSA全栈行动 👋]

# 一、背景：不再需要“两层皮”的方案

以前想在 Apple Watch 上用 Flutter 开发，基本没啥靠谱的方案。

主流的做法通常是：用 Flutter 把 iPhone 端写好，然后为了适配手表，还得专门用 SwiftUI 把手表端的界面重新写一遍，最后再通过 Method Channel 或者别的桥接手段让两者同步。这种“两层皮”的做法非常折磨人，你不仅要维护两套 UI，还得维护两套业务逻辑和平台决策，代码的复杂度直接翻倍。

虽然 Android 端的 Wear OS 对 Flutter 比较友好，但 Apple Watch 这一块一直是个缺口。好在现在有个叫 flutter-watchos 的第三方工具链，它直接把 watchOS 变成了 Flutter 的一个目标平台。

这玩意儿其实不是在搞 WebView 套壳，也不是什么远程渲染，而是实打实的 Flutter Engine 直接跑在 watchOS 设备上。也就是说，你写的 Dart 代码和 Flutter Widget 是直接在手表本地渲染的。

# 二、上手：flutter-watchos 实战流程

这个工具链的使用体验其实跟标准的 Flutter 开发非常接近，上手门槛并不高。

# 1、基本命令

它的入口非常熟悉，创建和运行的逻辑几乎没变：

# 创建一个支持 watchos 平台的项目
flutter-watchos create my_watch_app --platforms=watchos
cd my_watch_app

# 运行项目
flutter-watchos run

# 2、开发模式

我在测试时发现，它的开发流程跟平时玩 Flutter 差不多：

  • 模拟器调试：在 watchOS Simulator 上，你可以享受完整的开发闭环，包括 Hot Reload（热重载）、DevTools 以及极快的迭代速度。

  • 真机调试：在配套的物理手表上，由于 watchOS 不允许在硬件上进行 JIT 编译，所以代码会被编译成 AOT 模式安装到设备上。虽然真机没法像模拟器那样玩热重载，但 DevTools 依然可以连接上去，查看实时的帧率和性能表现。

这里有个建议：在把应用推向用户之前，一定要在真机上测性能。毕竟模拟器跑起来很流畅，但在手表这种功耗和散热极其敏感的设备上，性能表现跟模拟器完全是两码事。

# 三、深度细节：原生能力与避坑指南

虽然能跑起来是第一步，但要真正写出“像那么回事”的手表应用，还得处理好几个核心细节。

# 1、平台识别的坑

这是最容易踩坑的地方。flutter-watchos 在构建时会给 watchOS 一个独立的运行时身份，这让它能像原生应用一样运行。

你会发现，在手表上运行时，Platform.operatingSystem 会返回 watchos，Platform.isWatchOS 会返回 true。但要注意，此时 Platform.isIOS 竟然也是 true，且 defaultTargetPlatform 依然是 TargetPlatform.iOS。这其实是为了让 Cupertino 组件能直接套用 iOS 的风格，不需要改动 Flutter Framework。

避坑指南： 如果你在 lib/ 目录下写了一段通用的代码，里面直接用了 Platform.isWatchOS，那么你的应用在编译 iOS 或 Android 端时会直接报错，因为标准的 Dart SDK 里根本没有这个属性。

如果你想写跨平台逻辑，请务必使用 flutter_watchos 包提供的 FlutterWatchosPlatform.isWatch 方法。它能完美处理这种差异，在非手表设备上安全地返回 false。

# 2、原生能力集成

一个实用的插件系统是 Flutter 能否落地的关键。flutter-watchos 采用的是 Federated Plugin 模型，这让它能很好地扩展。

目前官方和社区已经适配了不少常用的包。下面我整理了一下目前的适配情况：

能力分类 已支持的包 / 解决方案 说明
基础存储 shared_preferences, flutter_secure_storage 无缝衔接，写法不变
传感器/设备 sensors_plus, geolocator, device_info_plus, battery_plus 获取物理设备数据
网络请求 http, dio, NetworkImage 内部处理了 watchOS 的 Socket 限制
交互与多媒体 url_launcher, video_player, audioplayers 支持标准的交互流程
适配包 flutter_watchos 相关实现包 需在 pubspec.yaml 中显式添加

特别提醒： 如果一个插件包含了 Native iOS 代码，你可能需要手动为它写一个 watchOS 的实现层。

# 3、手表端特有的交互

在手表上，有两个东西是你必须关注的：

  • Digital Crown (数码表冠)：它不仅能控制 Flutter 的 Scrollview 滚动，还可以通过 flutter_watchos 包获取原始的旋转数值，用来做一些类似拨盘、旋钮的自定义交互。

  • 文本输入：当你点击 TextField 时，它会自动唤起系统级的 watchOS 键盘。这种设计非常聪明，开发人员不需要处理复杂的键盘逻辑。

# 四、最后：总结与限制

flutter-watchos 目前还处于测试阶段（Closed Beta），虽然它展示了非常强悍的潜力，但我们还是要清醒地认识到它的边界。

目前还没解决的限制：

  • 环境要求：必须在 macOS + Xcode 环境下开发。

  • 编译限制：真机只能运行 AOT 编译后的版本，没法热重载。

  • 权限/发布：需要通过 App Store 的审核流程，且部分功能（如 Push Notifications）需要通过特殊的 AppDelegate 适配。

  • 设计压力：手表屏幕小、性能预算紧，所有的 Shader 效果（如波纹、翻页）都得慎重使用，一定要盯着性能指标看。

如果你想尝试，可以先从一个小功能入手，看看 Flutter 在手腕上的表现如何。总的来说，这套工具链让 Flutter 开发者终于不用在 SwiftUI 和 Dart 之间来回横跳了，这确实是个很棒的进步。
